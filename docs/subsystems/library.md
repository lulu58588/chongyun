# 库：指令、MCP 服务器、skill、hook、子 agent 与 RTK

<a id="library-instructions-mcp-servers-skills-hooks-subagents-and-rtk"></a>

库把每个 agent 应当知道的东西收在一处：每个 agent 在一次对话前读的指令、它能调用的 MCP 服务器、它能加载的 skill、它在自己回合的某些节点上运行的 hook，以及它能派活给的子 agent。崇云科技把这些写进每个 agent 自己的文件，用那个 agent 自己的格式，并且只取回自己写过的东西。那些文件里的其它内容都保持原样。包 `internal/library` 还给 agent 提供了 RTK——一个在模型读到之前先把 shell 输出削减掉的 CLI。

## 运行时路径

<a id="runtime-path"></a>

1. **编辑。** Library 页面或 `chongyun library` 会调用一个导出的函数，比如 `SaveServer`、`ServerAgents`、`InstallSkills`、`SkillAgents` 或 `SetSkillHow`。skill 页面和服务器页面各自都有 Select、Turn all on、Turn all off 和 Remove all。Select 的工具条调用 `SomeSkillsAgents` 或 `SomeServersAgents`（`/api/library/{skills,servers}/agents-some`），Turn all on 或 off 对显示出来的 agent 调用 `EverySkillAgents` 或 `EveryServerAgents`，Remove all 则调用 `RemoveSkills` 或 `RemoveServers`。hook 页面也有 Select 和 Remove all（`SomeHooksAgents`、`RemoveHooks`）。这些每一个都是一次改动，会像一次整体移除那样把每一项都取走（#1027）。Select 的工具条还有 Remove…（#1852），它先问一次并说明数量，只把挑中的名字发给 `RemoveSkills`、`RemoveServers` 或 `RemoveHooks`；勾上一个组或一部分的表头会把它们全挑上。没被移除的名字仍然被挑中，它的错误留在自己那行的位置（`pickErrs`），状态里会点名它；当所有名字都失败时，端点回答 400，面板保持打开。一行的 agent 标记一开始是 All（plugins/library/client.js 里的 `allChip`），它把这一项给所有显示出来且拿得住它的 agent，或者从它们那里全部取走；在加进一项之前挑选 agent 的那些选择器（从仓库或市场安装 skill、添加、收进或安装服务器）也有同样的 All：大多数一开始每个 agent 都是亮的，而单独一个 agent 要在其它每个上面各点一次（#1531）。
2. **改动。** `change` 在锁下编辑 `library.json` 并调用 `sync`。
3. **写入。** 对每个目标，`syncInstructions`、`syncMCP`、`syncHooks` 和 `syncSubagents` 用 agent 的格式写出崇云科技那部分，并把它记进 `Applied`。skill 被链进或复制进 agent 的 skill 文件夹。一个自复制之后被改过的副本会先被收进库里。
4. **结果。** `Result` 列出改动了哪些 agent、每一件没能给出去的东西对应一个 `Problem`，以及备份文件夹。每次改动的文件夹都是它自己的（`freshBackup`）：按毫秒命名，同一毫秒被另一次改动占用时后面加 `-2`、`-3`…，所以一次改动的副本绝不会和另一次的一样（`TestBackupsInOneMillisecond`）。

## 约束与失败行为

<a id="constraints-and-failure-behavior"></a>

- 崇云科技只取走 `Applied` 或它的标记说它写过的东西。用户自己那个以 skill 名字命名的文件夹绝不会被碰。MCP 条目里用户自己填的字段会保留。
- 一次编辑绝不会悄悄丢失。当某个 agent 的 skill 副本和库里都改过时，较新的编辑胜出，落败的那份和备份放在一起。
- 来自 GitHub 或一个 git 仓库的更新绝不会悄悄替换在这里改过的 skill。它会被拒绝，或者在一次更新多个时被跳过，直到用户说要替换它，而被替换掉的那一版会进备份。
- 副本的标记只有在它整个文件夹都被扫描过之后才确立它没变。如果某个子树或它的元数据读不了，副本留在原处，同步报一个 `Problem`；它不会被替换、重新链接或移除。等能读时，后一次同步会再试一次。同样的扫描失败也会让项目的副本或 Claude Desktop 的副本不被替换。
- 某个 agent 的失败是结果里的一个 `Problem`。它不会挡住其它 agent。
- 一次 MCP OAuth 签入在它的回调提交之前被取消或超时，绝不会保存迟到的 token，也不会改动已有的签入。回调的写入和流程的结束共用一把锁（[`mcpauth.go`](../../internal/mcpauth/mcpauth.go) 里的 `flow.keep`）；如果写入先赢，它会完成并先告诉那些 agent，然后才说做完了。取消不等于把已经提交的凭据登出。
- agent 够不到的服务器不会被写到它那里，`mcpFile.supports` 会说明原因。比如 Claude Desktop 不接受远程服务器，Codex、Goose、dsh、Grok、Command Code 和 Zed 都不接受 SSE。
- 服务器的 headers（远程）或环境变量（命令）可以把一个变量写成 `${NAME}`（#1250）。`library.json` 保留这个占位符，而 `refsOf` 给每种 MCP 格式该 agent 自己的语法，旁边注明该 agent 的来源：多数是 `${NAME}`，OpenCode 和 MiMo 是 `{env:NAME}`，Cursor 是 `${env:NAME}`，Codex 用它自己的键（`bearer_token_env_var`、`env_http_headers`、`env_vars`）。Goose 是 `${NAME}` 加 `env_keys`。dsh（DeepSeek Harness）得到一个 `!!js` 表达式，它在加载服务器时求值（#1435）：整个 `${NAME}` 是 `!!js process.env.NAME`，而文本和变量混在一起的值是文本作为 JSON 字符串字面量、用 `(process.env.NAME ?? "")` 连起来，所以用户的文本绝不会被当代码执行，而没设置的变量在它是空的。整个没被设置的变量会让 dsh 把这个服务器当作无效而排除。崇云科技只把那些形式读回成 `${NAME}`；其它任何 `!!js` 都让这条目保持用户的写法。没有语法的 agent（Claude Desktop、Antigravity、Kimi、Cline、ZCode、Zed、Devin、Alma、带 pi-mcp-extension 的 Pi）绝不会被写进这个值：`refsProblem` 让 `supports` 拒绝这个服务器，已经在那里的崇云科技条目会被取走，而 `AgentView.NoEnvRefs` 把它的标记变灰并给出原因。Codex 和 Goose 的额外键只在该服务器在那里指名变量时才是崇云科技的（`refKeys`），所以用户自己的 `env_vars` 或 `env_keys` 会保留。`CheckServers` 从崇云科技自己的环境里展开那个变量，没被设置的会标成 `novar` 并点名它。页面把这画成未检查（一个圆环，`lib-health unknown`），而不是红色：它对那个服务器什么都不说，因为 agent 可能会带着设好的变量启动它，就像 Codex 对它只在本地生效的 `codex_app` 那样（#2308）。它在 home 里启动命令服务器，并把 `PWD` 设成 home（Windows 上不设），就像一个从 home 启动的 agent 那样，绝不在崇云科技自己的工作文件夹里：一个从 Windows 开始菜单启动的崇云科技有 `C:\Windows\system32`，在那里一个往 `.` 里写文件的服务器会在应答之前退出（#1727，`TestCheckStdio`）。
- 在页面上被关掉的服务器工具（nf1qaz2w 报告）按服务器给出的名字保存在 `Server.DisabledTools` 里，并且只写给那些为它读一个设置的 agent（`toolsOffOf`），每个 agent 用自己的格式，并对照它的来源核对：

  - Gemini CLI：服务器条目里的 `excludeTools`（`docs/tools/mcp-server.md`；`mcp-client.ts` 按工具自己的名字丢弃它，google-gemini/gemini-cli 9b6e0265）。
  - Crush：服务器条目里的 `disabled_tools`（`internal/config/config.go` 里的 `MCPConfig`、`filterTools`，charmbracelet/crush df5b024a）。
  - Hermes Agent：服务器条目里的 `tools.exclude`，用原始名字（`tools/mcp_tool_registration.py`、`mcp-config-reference.md`，NousResearch/hermes-agent c5733167）。旁边的 `tools.include`、`prompts` 和 `resources` 是用户的。
  - Claude Code：它的 settings.json 里 `permissions.deny` 中的一条 `mcp__<server>__<tool>` 规则（`Target.Settings`，挨着 `.claude.json`；对 WSL 发行版则是发行版的那份）。deny 里一个光秃秃的工具名会把该工具从 Claude 的上下文里去掉（code.claude.com/docs/en/permissions）。两个名字都按 Claude Code 2.1.296 的拼法写：除字母、数字、`_` 和 `-` 之外的每个字符都写成 `_`。
  - OpenCode：opencode.json 顶层 `tools` 里的 `"<server>_<tool>": false`（opencode.ai/docs/mcp-servers，"Manage"），名字按 `packages/core/src/tool/mcp.ts` 里 `name()` 的拼法写；`packages/core/src/config/normalize.ts` 里的 `migrateTools` 把每一个变成一条 deny 规则（sst/opencode 0d61729b）。
  - 其它每个 agent（Cursor、Copilot 和 Goose，它们的列表只有白名单，Zed、Kimi、Pi、Grok、Devin、Antigravity、Alma、dsh、omp、ZCode、Command Code、Cline、WorkBuddy、CodeBuddy、Droid、Claude Desktop、MiMo Code、DevEco Code，以及 plugin 的 agent）都整个拿到这个服务器。它们的 `AgentView.ToolsOff` 是 false，而打开的工具列表会把那些拿到服务器却无法关掉单个工具的列出来。项目的文件和 Copy config… 同样不带任何被关掉的工具。
  崇云科技记下它加了什么（条目里的列表按服务器记在 `Applied.ToolsOff`，Claude Code 的规则和 OpenCode 的键记在 `Applied.ToolRules`），并且只取回那部分（`offList`）：用户本来就有的名字、规则或键是他的，在工具再次打开时仍然留着，用户自己设成 `true` 的 OpenCode 键绝不会被覆盖写。一个不是名字列表的列表，或 `permissions.deny`，是一个问题，绝不会被当成空，文件保持原样。那个键、以及 Claude Code 的 `permissions` 或 OpenCode 的 `tools`，在崇云科技写的成了最后一个时就会消失。编辑器的保存不发送任何工具，所以 `SaveServer` 保留那些被关掉的。
- 崇云科技自己的 MCP 服务器（`magpie-image`，以及任何由名为 `magpie` 的程序跑的 `mcp …`）跑的是本机的这个崇云科技（#1439）。`InstallServer` 用完整路径把本机的程序交给它（`update.Program`：是 AppImage 而不是它的挂载点；是 Homebrew 的 opt 链接而不是 Cellar 里的），而那个路径只在这台电脑上是对的。读库时以及每次改动之后，`heal` 会把这类程序不在本机的服务器（别的系统的路径、一个被移出 Downloads 的程序、光秃秃的 `magpie`）指向本机这个程序，于是 agent 和 `CheckServers` 拿到的就是它；一个确实在这台机器上的程序（另一个构建）和由任何别的程序跑的服务器都保持原样。被带走的库（`Collect`，用于备份或 WebDAV 或 S3 同步）把它写成光秃秃的 `magpie`，这样两台电脑带的是同一个包，同步不会把一台的路径写到另一台上；`Put` 随后把它读作那台电脑自己的程序。[`self_here.go`](../../internal/library/self_here.go)
- 被带走的库（`Collect`）带着每个 skill 的每一个文件，包括它的模板和别的二进制，单个文件上限 `maxCarried`（16 MiB），全部加起来上限 `maxCarriedAll`（32 MiB），在各个 skill 之间先挑最小的（`readSkills`），所以每个 skill 的文本都排在任何大文件之前。这个总量让一个封存的备份留在同步会读的 64 MiB 之内：文件在里面被 base64 了两次。被排除的东西列在 `Left` 里，`Put` 会在它放下的那个 skill 里保留本机的那份副本（`keepLeft`）。[`carry.go`](../../internal/library/carry.go)
- WorkBuddy 的服务器放在 `$WORKBUDDY_CONFIG_DIR/mcp.json`（默认 `~/.workbuddy`；WorkBuddy AI 这个国际版把自己的放在 `~/.workbuddy-ai`，#1494），CodeBuddy Code 的放在 `.mcp.json`、`mcp.json` 和 `~/.codebuddy.json` 里第一个存在的那个，按 `resolveMcpFilePath` 读它们的方式（#1266）。WorkBuddy 只有在用户在自己的 MCP 设置里打开过一次之后才连接一个服务器。它把那个批准记在 `mcp-approvals.json` 里，键是命令、参数和环境变量名或者 URL 的来源，所以改了这些就要重新问。崇云科技从不写这个批准，而服务器页面在把服务器给 WorkBuddy 或 WorkBuddy AI 时会按构建的名字说明这一点。
- Alma 的服务器在所有系统上都放在 `~/.config/alma/mcp.json`（它的 home，不是它的数据文件夹），按它自己的 MCP 设置写的方式：`command`/`args`/`env`，或者 `url`/`headers`，而 `transport: "sse"` 只对 SSE 有效（#1292）。Alma 在启动时和它的 MCP 设置刷新时读那个文件，所以运行期间给它的服务器会在那之后到达。
- Grok App 独立的 home（在自定义 provider 上用 Use，`GROK_HOME` 放在它数据文件夹下的 `agent-home`）在 `AGENTS.md` 里拿指令，在崇云科技那个通道所在的同一个 `config.toml` 的 `[mcp_servers]` 里拿 MCP 服务器，在 `skills/` 里拿 skill，hook 是那个配置里的 `[[hooks.<Event>]]` 表，它还会读 `~/.agents/skills`。共享模式留在 Grok Build 的 `~/.grok` 那一行。RTK 把 Grok App 和 Grok Build 都列出来，开关是关的：`rtk init` 没有 Grok 这个 agent。
- Zed 的服务器放在崇云科技设置它模型的那个 settings.json 的 `context_servers` 里（`agent.zed`：macOS 上是 `~/.config/zed`，Linux 上是 `$XDG_CONFIG_HOME/zed`，Windows 上是 `%APPDATA%\Zed`，或者 `$MAGPIE_ZED_CONFIG_DIR`），写成 `command`/`args`/`env` 或 `url`/`headers`（`ContextServerSettingsContent`，zed-industries/zed 2c99f547）。这个文件是 JSONC：它被就地编辑，所以用户的注释、其它设置和自己加的服务器都留着，而崇云科技那个条目里的 `enabled`、`remote`、`timeout` 和 `oauth` 是用户的。Zed 只说可流式的 HTTP（它的 `http.rs` 只发 POST），所以没有 SSE。由 Zed 的扩展配置的条目（只有 `settings` 而没有 command 或 url）绝不会被覆盖写：同名的服务器会被拒绝给 Zed（`mcpFile.foreign`），并要求换一个名字。Zed 会在文件变化时重新加载它。
- 一个没有某项的容身之地的 agent 会被 `Takes` 拒绝，绝不会被记成拿到了它。拒绝会列出这里哪些 agent 拿这一项（`takenBy`），并说明它改去哪儿（`noPlace`）：OpenChamber 读的是 OpenCode 的全局 AGENTS.md、skill 文件夹和 opencode.json（它服务端的 `shared.js`），所以它从 OpenCode 那里拿；Claude Desktop 的聊天把它的指令放在它自己的设置里，配 Claude 账号，而它的 Code 标签页读的是 Claude Code 的。plugin 的 agent 若其 `agent.library` 没为某项指名地方，那一项就会被拒绝，而拒绝会点名它的 plugin 本该设置的那个键。
- 移除 RTK 从不使用 `rtk init --uninstall`。那条命令会把 Gemini 的 `GEMINI.md` 整个删掉，还会连带移除 Claude Code、OpenCode 和 Cursor。
- hook 是逐条记录的，按写下来的样子（`Applied.Hooks`，按规范的 JSON 比较）。崇云科技只取走仍和它写的一模一样的条目；用户改过的从此就是用户的，旁边的用户自己的 hook 也留着。解析不过的 hooks 文件是一个问题，绝不会被写。Codex 把每个 hook 的信任记在 config.toml 的 `[hooks.state."<path>:<event>:<group>:<handler>"]` 里，按位置作键，所以崇云科技取走一个组时，`codexRekey` 会把它后面那些组的用户信任挪到新位置。
- 被带走的库（备份、WebDAV、S3、profile 包）还不带 hook。
- 子 agent 文件按崇云科技写下的内容的哈希记录（`Applied.Subagents`）。崇云科技只覆盖或取走仍和它写的一模一样的文件；用户改过的从此就是用户的，页面会这么说。用户自己那个同名的文件绝不会被覆盖写：那个 agent 会得到一个问题。崇云科技的文件被用户删掉后，下一次同步会重新写出来。Cursor 的 `~/.cursor/agents` 只有 Cursor app 读；cursor-agent CLI 只读项目的 `.cursor/agents`。WSL 发行版里的 agent 拿不到子 agent，没有用户级子 agent 文件夹的 agent 也一样（Kimi、Goose、Crush、Qoder、CodeBuddy、iFlow、Kiro）。被带走的库还不带子 agent。
- CC Switch 自己的 skill 文件夹只会被读。
- 读这一页绝不会等着把 skill 读完（#541）。`Read` 会把某个 agent 自己的 skill 和另一个 agent 里的同名 skill 做比较（`sameTree`），并给每个以副本形式给出的库 skill 算哈希（`hashFiles`，为了 `behind`）。两者都对照着文件夹的一份标记来保存（每个文件和链接的路径、类型、大小和 mtime，[`treememo.go`](../../internal/library/treememo.go) 里的 `stamper`），而这份标记由同一次遍历取得——也就是比较或算哈希的那次遍历，在打开任何文件之前；之后的一次读取只遍历文件夹而不打开文件，标记一致时就复用答案。只有对 `settleFor`（3s）内没被动过的文件夹做的一次完整读取的结果才被保留：走不通或读不了的文件夹，或者刚刚被写过的，下一次会重读，绝不会被当作没变。保持了文件大小和 mtime 的改写是看不见的。`Glance`（`GET /api/library?glance=1`）是没有那两项的页面，标为 `partial`；页面先画它，然后再做完整读取，而完整读取是在放开库的锁之后才跑 `behind` 和 `foundSkills` 的，所以一次改动也不会被它们拖住。
- 页面的一次读取（`Read`、`Glance`）在途中会跟随链接，走到几百个路径，其中大多数要走很多遍：每个 skill 都要走一遍每个 agent 的 skill 文件夹，每个来源都要走一遍 CC Switch 的文件夹和共享文件夹。读取持着锁的时候，`resolve` 对途中的每个条目只看一次（[`linkmemo.go`](../../internal/library/linkmemo.go) 里的 `lookPart`）：一次 `Lstat`，链接还要一次 `Readlink`。读取之后什么都不保留，所以两次查看之间在磁盘上新建或移动的链接会在第二次显示出来。因别的原因（而不是它不在那儿）看不了的条目属于未知，会再看一次。有一次读取花了大约 10000 次查看；在 oxyuan 的 Windows 机器上那大约是每次访问 1.3s（#1771）。
- 一起安装的 skill（`InstallSkills`、`InstallMarketSkill`、`AddNewSkills`，经由 `installFrom` 和 `installChange`）是各自单独安装的。库里从同一来源列出的那个 skill，或者库自己 skill 文件夹里装着完全相同文件的那个文件夹（一次在库保存之前就停下的安装留下的），算是已经有了，列在 `Result.Had` 里。它的文件绝不会被写，所以用户的改动留着。同名的另一个 skill（列出来的或只在那文件夹里的），或者一个读不了的文件夹，都保持原样，列在 `Result.Skipped` 里并说明原因。其余的会被安装并列在 `Result.Installed` 里。只有当既没安装成什么、也没有已有什么时，这次改动才失败，并给出第一个原因。
